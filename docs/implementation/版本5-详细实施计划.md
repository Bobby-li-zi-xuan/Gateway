## 1. 目标与范围

版本 5 完成后，系统支持：

- **配置即代码**：模型别名与策略、渠道、令牌初始定义、插件及配置、限流与预算限额、执行治理参数全部写进一份 `gateway.yaml`；支持 `include` 拆分（渠道、策略分文件），合并后统一校验。
- **Schema 校验**：启动时完整校验（结构、类型、引用关系、权重和、字段枚举）；错误输出"文件 + 路径 + 原因"，可读性强；**校验上收**——V1~V4 散落在各组件构造器的启动校验统一收敛到 `ConfigValidator`，单一来源。
- **热更新（copy-on-write）**：加载后配置整体不可变；热更新五步（解析 → Schema 校验 → 预检 → 通知组件重建（全部成功才替换内部引用，任一步失败整体回滚）→ 原子替换全局引用）；非法配置不生效，当前配置继续；**在途请求无感知**。
- **版本化与回滚**：每次生效配置有版本号与变更说明；保留最近 N 版，支持一键回滚（回滚也走完整校验与预检）。
- **运行对象联动**：渠道权重 / 启停变更重建缓存并原子替换（不重建 HTTP 连接池）；策略 / 插件变更重建对应实例（插件实例不可变，替换引用生效）；预算限额变更更新上限（**已用量保留**，重置是显式操作）；通知按依赖顺序下发（渠道 → 策略 → 插件 → 治理），任何一步失败整体回滚。
- **Admin API（带鉴权）**：管理密钥 + IP 白名单（与调用方令牌体系分开）；覆盖渠道 / 令牌 / 策略 / 插件 / 用量 / 决策日志查询；配置管理端点（GET 当前配置、PUT 热更新、POST 回滚）；写操作校验参数并返回明确错误；删除类操作显式确认。
- **审计日志**：管理写操作全部记录（操作者、操作类型、目标对象、变更前后摘要 diff、结果、时间）；独立审计表；按操作者 / 对象 / 时间过滤查询；与请求日志（决策日志）分离。
- **版本 4 功能回归**：令牌 / 限流 / 预算 / 计量 / 渠道管理不回退。

**非目标**（版本 5 不做什么）：

- 不实现管理后台前端页面（版本 6 可选）。
- 不实现语义缓存、安全护栏、协议互转（版本 6）。
- 不做配置的分布式一致性（单节点场景，远期）。
- 不做运行时令牌的配置化管理（安全：凭证不能进配置明文；`tokens` 段仅在启动时作为种子导入——执行者是 `TokenManager` 启动时读 `ConfigService.current()` 快照的 tokens 段导入 DB（V4 语义"创建即入库"），`agw_demo_*` 自动演示令牌逻辑保留（V4 兼容性约定）；运行时令牌变更一律走 Admin API）。
- 不做外部文件监听自动热更（`gateway.config.path` 支持 `file:` 外部路径，但重载仍由 Admin API 触发；文件监听留给版本 6 可观测性）。
- 不引入配置中心 / 版本控制存储（回滚用内存历史，重启即丢——文档标注）。

## 2. 与现有代码的关系（先盘点，再动手）

### 2.1 与版本 4 的关系（重要：配置权威与 DB 覆盖的取舍）

版本 5 的核心变化是**配置权威**：`gateway.yaml` 成为渠道 / 策略 / 插件 / 限额的唯一权威来源，热更新通过 `ConfigService` 原子替换。这带来两处与 V4 的语义调整（V4 计划第 24 节已预留"V5 只需加鉴权层与审计表"，此处进一步说明）：

1. **V4 的 `ChannelStore` DB 覆盖机制移除**：V4 中 DB 保存的渠道权重 / 启停状态在启动时覆盖 model.yml 同 id 渠道（DB 优先）。V5 中权重 / 启停完全由配置决定（否则热更新改权重会被 DB 值覆盖，演示 A 不生效）。`channel` 表**保留**，仅存渠道软删标记（`deleted`）供历史用量 / 审计追溯，以及 V4 演示数据的兼容；表中的 `enabled` / `weight` 列成为**只读遗留列**（V4 的 setEnabled/setWeight 写库逻辑不再执行，列保留兼容既有数据，不删）。
2. **V4 的 `GovernanceAdminController` 升级**：V4 管理端点免鉴权（V4 计划明示"V5 将整体替换为带鉴权的 Admin API"），V5 加管理密钥 + IP 白名单；渠道写操作语义从"直写 ChannelStore"改为"配置热更新"（见第 13 节）；令牌管理保持 DB 驱动（凭证不进配置）；接口路径保持一致（`/v1/admin/*`）。
3. **`DecisionDebugController`（/v1/debug/decisions）**：注释已声明"版本 5 由 Admin API 取代"——V5 在 Admin API 提供 `/v1/admin/decisions`，旧端点保留路由（学习演示兼容），文件不删除（如需删除请先确认）。
4. **`GovernanceProperties` 变纯绑定类**：V4 中是 `@ConfigurationProperties` Bean（前缀 `gateway.governance`）；V5 改为由 `ConfigLoader` 手动绑定、放入不可变快照。**字段名与缺省值保持 V4 定义不变**（V4 计划 24 节预留：缺省值结构就是热更新后运行时快照的形状）。

### 2.2 组件改造总表（V5 的两大手术）

V5 有两处影响面大的改动，动手前先确认清单：

**手术一：配置绑定方式切换。** 所有构造器注入 `GatewayProperties` 的组件，改为注入 `ConfigService`（从 `current()` 读快照），并实现 `ConfigAware.onConfigChanged` 支持重建。好消息：`GatewayProperties` 去掉 `@ConfigurationProperties` 注解后不再是 Spring Bean，**漏改的组件会在启动时报 `NoSuchBeanDefinitionException`（No qualifying bean of type 'GatewayProperties'），启动期强提示**，不会静默出错。

| 现有文件 | 现状 | 处理方式 |
|---|---|---|
| `GatewayProperties` | `@ConfigurationProperties` + `@Configuration` 两个注解，前缀 gateway | 移除**两个注解**变纯绑定类（只去 @ConfigurationProperties 的话 @Configuration 仍使其成为 Bean——"去注解 → 非 Bean → 启动强提示"机制失效，会静默注入全默认值 props）；保留 @Data 结构与字段缺省值；由 ConfigLoader 手动绑定（第 7 节）；**不含 governance 嵌套字段**（该段由 GovernanceProperties 绑定，避免双绑定） |
| `GovernanceProperties`（governance/config） | V4 `@ConfigurationProperties` Bean，前缀 gateway.governance | 同上（去注解变纯绑定类）；字段与缺省值不动 |
| `ModelRegistry` | 构造器注入 props + init() 构建对象图 + 启动校验 | 🖊 H3：改注入 ConfigService，启动校验上收 ConfigValidator，对象图 COW（volatile State） |
| `PolicyManager` | 构造器注入 props + 注册内置策略 + 交叉校验 | 改注入 ConfigService；交叉校验上收；policies 表 COW |
| `PluginRegistry` | 构造器注入 props + 按 name 挂载 SPI | 改注入 ConfigService；挂载表 COW；新增 `enabled` 支持（false 不挂载） |
| `Scorer` | 构造器注入 props（defaultOutputTokens） | 参数改 volatile 字段 + rebuild（读快照） |
| `DecisionLogStore` | 构造器注入 props（logSize）+ 环形缓冲 | 改注入 ConfigService；logSize 变更时重建环形缓冲（保留现有条目）；新增 findByRequestId |
| `ModelStateStore` | 构造器注入 props（ewmaAlpha/errorRateAlpha） | 参数改 volatile 字段 + rebuild |
| `HealthChecker` | 构造器注入 props + @PostConstruct 定时探活 | 参数改 volatile 字段 + rebuild（intervalSeconds 变更时重建调度器） |
| `ExecutionPolicyManager`（V3） | V3 构造器绑定 execution 参数 | 参数快照改从 ConfigService 读 + rebuild |
| `ChannelStore`（V4） | 启动时 DB 覆盖同 id 渠道权重/启停 | 改为从配置快照重建（**移除 DB 权重覆盖**，见 2.1）；DB 仅软删标记 |
| `AvailabilityFilter`（V2 第 2 道关卡） | 读 ChannelStore.isEnabled（V4 增加） | **无需改动**——继续读 `ChannelStore.isEnabled`（store 已由配置 rebuild + DB deleted 恢复，见 10.3），渠道启停热更经 store 间接生效 |
| `BudgetManager`（V4） | 预算实体（上限 + used） | rebuild：按"作用域 + 周期"更新上限，**已用量保留**（第 11 节） |
| `RateLimiter`（V4） | defaultQps/defaultRpm 参数 | 参数改 volatile 字段 + rebuild（已有窗口保留） |
| `GovernanceService` / `GovernanceFilter`（V4） | 注入 GovernanceProperties | 改注入 ConfigService（governance 段从快照读） |
| `GovernanceAdminController`（V4） | /v1/admin/* 免鉴权管理端点 | 加鉴权（拦截器自动覆盖）+ 渠道语义改配置驱动 + 补端点 + 审计（第 13 节） |
| `DecisionDebugController` | /v1/debug/decisions | 保留路由；Admin API 新增 /v1/admin/decisions |
| `ChatGatewayService` | V4 治理接线主流程 | **不动**（组件内部参数读取路径改造，主流程零改动） |
| `HttpClientFactory` | 全局单例 HttpClient（连接池按上游地址 host:port 复用，与渠道 id 无关） | **不动**——"热更新不重建连接池"天然满足 |
| `application.yaml` | spring.config.import model.yml | 移除 import；新增 `gateway.config` 加载器参数段 |
| `model.yml` | Spring 导入的配置源 | **改名为 `gateway.yaml`**（含 include / admin / config 支持）；model.yml 删除前先确认 |

> 路径前缀：`ai-gateway/src/main/java/com/aigateway/`。V5 新代码放 `config/` 包（model / loader / validate / service / spi 子包）与 `governance/admin/`、`governance/audit/` 子包。

**手术二：启动校验上收。** V1 的 ModelRegistry 校验（重复 alias、渠道引用、非正权重）、V2 的 PolicyManager 交叉校验（strategy 存在、CONDITIONAL select 子集）、V3 的 ExecutionPolicyManager 校验、V4 的渠道/插件校验——全部收敛到 `ConfigValidator`（第 8 节）。组件 rebuild 只做"构建对象图"，不再抛 `invalid_config`；校验错误统一在加载层以可读形式暴露。这样热更新与启动共用同一套校验，**不存在"启动能过、热更不行"的口径差**。

## 4. 依赖（pom.xml）

**新增一项依赖**（其余不动）：

```xml
<!-- ai-gateway/pom.xml 新增（YAML 序列化用：ConfigLoader 合并结果 → 快照 YAML 原文） -->
<dependency>
    <groupId>com.fasterxml.jackson.dataformat</groupId>
    <artifactId>jackson-dataformat-yaml</artifactId>
</dependency>
```

- ⚠️ 2026-08-10 审查修正：`spring-boot-starter-json` **不含** jackson-dataformat-yaml（只含 databind/jdk8/jsr310/parameter-names），`new ObjectMapper(new YAMLFactory())` 必须显式加依赖（Boot 3.2 管理版本 2.15.x，无需写版本号）。
- YAML 解析（反序列化）：Spring Boot 自带 SnakeYAML（`spring-boot-starter` 传递依赖）；`YamlPropertySourceLoader` / `Binder` 来自 spring-boot（配置绑定用）。
- H2 / JDBC：V4 已引入。
- Jackson databind：已有（JSON 序列化 / 转 Map 用）。

理由（面试可讲）：

- 配置加载、绑定、校验全部用 Spring Boot 自带能力（`YamlPropertySourceLoader` 扁平化 + `Binder` 宽松绑定），不引第三方配置框架；
- 校验器基于 SnakeYAML 解析出的 `Map` 自研（学习点：错误定位到"路径 + 原因"比框架错误可读得多）；
- 审计走 V4 已建好的 `JdbcTemplate`，不引 ORM。

```java
public record GatewayConfig(
        int version,                     // 版本号（从 1 递增，每次生效 +1）
```

## 7. 配置加载与合并（关键代码段 S3，Codex）

> 路径：`ai-gateway/src/main/java/com/aigateway/config/loader/ConfigLoader.java`

职责：读取主文件（`gateway.config.path`，支持 classpath / file）→ 展开 `include`（同构文件，section 级合并，同 section 跨文件重复报错）→ 序列化合并结果得到 `yaml` 原文 → 绑定 `GatewayProperties` / `GovernanceProperties` / `AdminProperties` → 产出 `ParsedConfig`（供校验器与快照使用）。

```java
package com.aigateway.config.loader;

/** 加载产物：校验器（Map）与快照（绑定对象 + YAML 原文）共用。 */
public record ParsedConfig(
        Map<String, Object> root,          // 合并后的 gateway 节点（递归 Map，校验器用）
        String yaml,                       // 合并后的 YAML 原文（快照保存，GET 回传用）
        GatewayProperties props,
        GovernanceProperties governance,
        AdminProperties admin) {
}
```

实现要点（Codex，对照学习版 4.1）：

1. **加载**：用 SnakeYAML `Yaml.load(inputStream)` 得到主文件 Map；若 `root.get("gateway")` 不是 Map 报错"缺少 gateway 顶层节点"。
2. **include 展开**（只展开一层，禁止嵌套 include 以简化）：
   - 读 `gateway.include`（List<String>）；每个文件用相对主文件目录解析（classpath 文件按 classpath；file: 按父目录）；
   - 逐个加载为 Map，取其 `gateway` 节点（允许缺 gateway 键报错"include 文件必须与主文件同构"）；
   - 合并规则：**section 级**——`channels` / `models` / `policies` / `plugins` / `health` / `decision` / `execution` / `governance` / `tokens` / `admin` 等 key 只允许出现在一个文件中；跨文件重复 → `ConfigError.at("include", "section [" + key + "] 重复定义于 " + 文件名)`；
   - `include` 键本身不进入合并结果（展开后删除）。
3. **序列化**：`ObjectMapper(new YAMLFactory())` 把合并后的 `gateway` Map 写回 YAML 文本（快照的 `yaml` 字段）。
4. **绑定**：`YamlPropertySourceLoader.load("gateway", new ByteArrayResource(yamlText))` 得到扁平 PropertySource → `new Binder(new MapConfigurationPropertySource(ps.getSource()))` 分别 bind `GatewayProperties`（prefix "gateway"）、`GovernanceProperties`（prefix "gateway.governance"）、`AdminProperties`（prefix "gateway.admin"）。绑定失败（类型不符等，正常已被校验器拦截）→ 包装为 ConfigError 抛出。
5. **文件读取失败**（路径不存在 / YAML 语法错误）：SnakeYAML 抛 `YamlException` → 包装为 ConfigError（"无法解析 YAML: 具体原因"）。YAML 语法错误是**启动即失败**（ConfigService 构造时加载），保证"配置错误在启动时暴露"。
6. **对外 API（热更新与 AdminService 共用）**：
   - `loadMain()`：读主文件 + include 合并 + 绑定 → `ParsedConfig`（启动用）；
   - `parse(String yamlText)`：对提交的 YAML 文本走同一套"合并（重新展开 include）→ 绑定"→ `ParsedConfig`（热更新用；include 相对路径按主文件目录解析）；
   - `parseRoot(String yamlText)`：仅反序列化 → 返回 `gateway` 节点的递归 Map（AdminService 的"读-改-写"用）；
   - `tokensOf(String yamlText)`：返回 `gateway.tokens` 段的**原样提取**（不做字段规范化/补缺省，保证与 `parsed.root().get("tokens")` 结构一致可直接对比；预检对比新旧 tokens 用，见 §9.2）。

关键代码（绑定部分）：

```java
private GatewayProperties bindGateway(Map<String, Object> root) throws Exception {
    String yamlText = yamlMapper.writeValueAsString(root);
    var ps = new YamlPropertySourceLoader().load("gateway", new ByteArrayResource(yamlText)).get(0);
    Binder binder = new Binder(new MapConfigurationPropertySource(ps.getSource()));
    return binder.bind("gateway", Bindable.of(GatewayProperties.class)).get();
}
```

## 8. Schema 校验器（关键代码段 S4，🖊 H1）

> 路径：`ai-gateway/src/main/java/com/aigateway/config/validate/ConfigValidator.java`

### 8.1 校验规则（先背下来）

| 类别 | 规则 | 错误示例 |
|---|---|---|
| 结构 | `gateway` 顶层节点由加载器保证（缺失报错）；校验器管 section 白名单（未知 section 报错）与 models 非空（V1 的"未配置任何模型"兜底上收） | `gateway.xxx → 未知配置段` / `gateway.models → 未配置任何模型` |
| 类型 | 数值字段必须是数值（weight / priceIn / priceOut / qualityScore / latencyProfileMs / 各限值），布尔字段必须是布尔，列表字段必须是列表 | `gateway.channels[0].weight → 必须是数字，实际是字符串 "10"` |
| 模型画像 | `qualityScore` 配置了必须在 0~1；`latencyProfileMs` 配置了必须 > 0（V2 规则上收） | `gateway.models[0].candidates[1].qualityScore → 必须在 0~1` |
| 引用 | `candidates[].channelId` 必须存在于 channels；`models[].strategy` 必须存在于 policies；CONDITIONAL 的 `defaultStrategy` 必须是 MULTI_OBJECTIVE；CONDITIONAL `rules[].select` 必须是该别名候选的子集 | `gateway.models[0].candidates[1].channelId → 引用了不存在的渠道: mock-c` |
| 条件规则结构 | CONDITIONAL 的 `rules[].when.signal` 非空、`op` ∈ {EQ, NE, IN}、`select` 非空；`value` 类型约束：IN 必须是 List、EQ/NE 必须是标量（V2 validateConditional 上收，避免运行期 ClassCastException） | `gateway.policies[3].rules[0].when.op → 不支持的 op: GT` |
| 权重和 | MULTI_OBJECTIVE 的 `weights` 必须四因子齐全（latency/cost/quality/health）、各值 > 0 且和 ≈ 1（误差 1e-6）（V2 validateWeights 上收） | `gateway.policies[2].weights → 权重和 = 0.8，必须为 1` / `缺少 cost 因子` |
| 枚举 | provider / scope / op / type / period / scopeValue / exceedAction / quotaType 等枚举值 | `gateway.channels[0].provider → 不支持的 provider: xxx` |
| 插件 | `plugins[].name` 必须能在 SPI 注册表中找到（注入 `List<GatewayPlugin>`）；同名挂载去重；`plugins[].enabled` 缺省 true；插件自检 `plugin.validate(config)`（如 keywordRegex 必须能编译） | `gateway.plugins[0].name → 未注册的插件: foo` / `重复挂载: canary` |
| 凭证 | `credentialsRef` 必须是空 / `env:` 前缀（不查变量存在性——V1 语义：空值 = 无密钥；管理密钥 env 引用缺失则 fail-closed，见第 12 节） | `gateway.channels[0].credentialsRef → 只支持 env: 引用: xxx` |
| execution | V3 的 15 条参数域校验全部上收：`totalMs > 0`；`defaultTimeout` 四层 > 0；`retry.maxAttemptsPerCandidate >= 1`、`jitterRatio ∈ [0, 0.5]`、`backoffBaseMs <= backoffMaxMs`、`retryableStatuses` 非空；`circuitBreaker.windowSize >= 10`、`minimumRequests ∈ [1, windowSize]`、`failureRateThreshold` / `slowCallRateThreshold ∈ (0, 1]`、`openDurationMs > 0`、`halfOpenMaxRequests >= 1`；`cooldown.consecutiveFailures >= 1`、`cooldownMs > 0`、`maxCooldownMs >= cooldownMs` | `gateway.execution.retry.jitterRatio → 必须在 [0, 0.5]` |
| tokens 段 | 启动种子令牌的字段校验（name 非空、quotaLimit > 0 或 -1、quotaType ∈ {TOKEN, COST}、period 枚举等）；tokens 段仅启动导入，热更新不接受变更（预检，第 9 节） | `gateway.tokens[0].quotaType → 不支持的取值: xxx` |

校验器**纯函数式**：输入 `ParsedConfig.root`，输出 `List<ConfigError>`；不抛异常、不修改任何状态。启动与热更新共用同一校验器（口径一致）。

### 8.2 主逻辑（代码段 S4，🖊 H1 全部手敲）

```java
package com.aigateway.config.validate;

import com.aigateway.config.loader.ParsedConfig;
import com.aigateway.config.model.ConfigError;
import com.aigateway.plugin.spi.GatewayPlugin;
import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

/**
 * 配置 Schema 校验器（🖊 H1 手敲）。
 *
 * 设计心法：
 * - 校验是"纯函数"：输入 ParsedConfig，输出错误列表。不抛异常、不改状态，
 *   启动与热更新共用，不存在"启动能过、热更不行"的口径差；
 * - 错误定位到路径（gateway.channels[0].weight）而非行号——
 *   路径是运维可以直接 grep 的坐标，比行号更可读；
 * - 一次返回全部错误（而不是"第一个错误就停"）：管理员一次改完所有错，
 *   体验远好于"改一个错、提交一次、再报一个错"。
 */
@Component
public class ConfigValidator {

    private static final double WEIGHT_EPSILON = 1e-6;

    /** 插件 SPI 实例表（按 name）——插件引用校验需要运行时知识，注入注册表 */
    private final Map<String, GatewayPlugin> pluginByName;

    public ConfigValidator(List<GatewayPlugin> plugins) {
        Map<String, GatewayPlugin> map = new java.util.HashMap<>();
        for (GatewayPlugin p : plugins) {
            map.put(p.name(), p);
        }
        this.pluginByName = Map.copyOf(map);
    }

    /** 校验合并后的配置，返回全部错误（空 = 通过）。 */
    public List<ConfigError> validate(ParsedConfig parsed) {
        List<ConfigError> errors = new ArrayList<>();
        // root 就是 gateway 节点（ConfigLoader 保证顶层 gateway 存在；section 直接取）
        Map<String, Object> g = parsed.root();

        // 1. 未知 section 白名单（新增 section 要同步加入）
        Set<String> known = Set.of("health", "decision", "execution", "channels",
                "models", "policies", "plugins", "governance", "tokens", "admin");
        for (String key : g.keySet()) {
            if (!known.contains(key)) {
                errors.add(ConfigError.at(key, "未知配置段"));
            }
        }

        // 2. 渠道：id 唯一 + provider 枚举 + credentialsRef 格式 + weight 类型
        List<Map<String, Object>> channels = list(g.get("channels"), "channels", errors);
        Set<String> channelIds = new HashSet<>();
        for (int i = 0; i < channels.size(); i++) {
            String p = "channels[" + i + "]";
            Map<String, Object> c = channels.get(i);
            Object id = c.get("id");
            if (id == null || id.toString().isBlank()) {
                errors.add(ConfigError.at(p + ".id", "渠道 id 不能为空"));
            } else if (!channelIds.add(id.toString())) {
                errors.add(ConfigError.at(p + ".id", "重复的渠道 id: " + id));
            }
            if (c.get("provider") == null || c.get("provider").toString().isBlank()) {
                errors.add(ConfigError.at(p + ".provider", "渠道 provider 不能为空"));
            } else {
                requireEnum(c.get("provider"), Set.of("openai-compatible"),
                        p + ".provider", errors);
            }
            Object cred = c.get("credentialsRef");
            if (cred != null && !cred.toString().isBlank()
                    && !cred.toString().startsWith("env:")) {
                errors.add(ConfigError.at(p + ".credentialsRef",
                        "只支持 env: 引用: " + cred));
            }
            requireNumber(c.get("weight"), p + ".weight", errors);
        }

        // 3. 模型：alias 唯一 + 候选非空 + 候选引用渠道存在 + 权重为正 + 价格非负
        List<Map<String, Object>> models = list(g.get("models"), "models", errors);
        if (models.isEmpty()) {
            // V1 的"未配置任何模型"兜底上收：一个模型都没有的网关没有意义
            errors.add(ConfigError.at("models", "未配置任何模型"));
        }
        Set<String> aliases = new HashSet<>();
        for (int i = 0; i < models.size(); i++) {
            String p = "models[" + i + "]";
            Map<String, Object> m = models.get(i);
            Object alias = m.get("alias");
            if (alias == null || alias.toString().isBlank()) {
                errors.add(ConfigError.at(p + ".alias", "模型 alias 不能为空"));
            } else if (!aliases.add(alias.toString())) {
                errors.add(ConfigError.at(p + ".alias", "重复的 alias: " + alias));
            }
            List<Map<String, Object>> candidates = list(m.get("candidates"),
                    p + ".candidates", errors);
            if (candidates.isEmpty()) {
                errors.add(ConfigError.at(p + ".candidates", "alias[" + alias + "] 没有任何候选"));
            }
            for (int j = 0; j < candidates.size(); j++) {
                String cp = p + ".candidates[" + j + "]";
                Map<String, Object> cand = candidates.get(j);
                Object channelId = cand.get("channelId");
                if (channelId == null || !channelIds.contains(channelId.toString())) {
                    errors.add(ConfigError.at(cp + ".channelId",
                            "引用了不存在的渠道: " + channelId));
                }
                Object weight = cand.get("weight");
                requireNumber(weight, cp + ".weight", errors);
                if (weight instanceof Number w && w.doubleValue() <= 0) {
                    errors.add(ConfigError.at(cp + ".weight", "权重必须 > 0"));
                }
                requireNonNegative(cand.get("priceIn"), cp + ".priceIn", errors);
                requireNonNegative(cand.get("priceOut"), cp + ".priceOut", errors);
                // V2 规则上收：qualityScore 必须在 0~1；latencyProfileMs 必须 > 0
                Object qs = cand.get("qualityScore");
                if (qs instanceof Number q && (q.doubleValue() < 0 || q.doubleValue() > 1)) {
                    errors.add(ConfigError.at(cp + ".qualityScore", "必须在 0~1"));
                }
                Object lat = cand.get("latencyProfileMs");
                if (lat instanceof Number l && l.doubleValue() <= 0) {
                    errors.add(ConfigError.at(cp + ".latencyProfileMs", "必须 > 0"));
                }
            }
        }

        // 4. 策略：name 唯一 + type 枚举 + weights 和为 1 + CONDITIONAL 回退引用 + select 子集
        List<Map<String, Object>> policies = list(g.get("policies"), "policies", errors);
        Set<String> policyNames = new HashSet<>();
        for (int i = 0; i < policies.size(); i++) {
            String p = "policies[" + i + "]";
            Map<String, Object> pol = policies.get(i);
            Object name = pol.get("name");
            if (name == null || name.toString().isBlank()) {
                errors.add(ConfigError.at(p + ".name", "策略 name 不能为空"));
            } else if (!policyNames.add(name.toString())) {
                errors.add(ConfigError.at(p + ".name", "重复的策略名: " + name));
            }
            Object type = pol.get("type");
            requireEnum(type, Set.of("MULTI_OBJECTIVE", "WEIGHTED_RANDOM", "CONDITIONAL"),
                    p + ".type", errors);
            if ("MULTI_OBJECTIVE".equals(type)) {
                Object weightsNode = pol.get("weights");
                if (weightsNode instanceof Map<?, ?> weights) {
                    // V2 validateWeights 上收：四因子齐全（latency/cost/quality/health）+ 各值 > 0 + 和 = 1
                    Set<String> required = Set.of("latency", "cost", "quality", "health");
                    Set<String> present = new HashSet<>();
                    double sum = 0;
                    for (Object k : weights.keySet()) {
                        present.add(k.toString());
                    }
                    for (String factor : required) {
                        if (!present.contains(factor)) {
                            errors.add(ConfigError.at(p + ".weights", "缺少 " + factor + " 因子"));
                        }
                    }
                    for (Object v : weights.values()) {
                        if (v instanceof Number n) {
                            if (n.doubleValue() <= 0) {
                                errors.add(ConfigError.at(p + ".weights", "权重值必须 > 0: " + v));
                            }
                            sum += n.doubleValue();
                        } else {
                            errors.add(ConfigError.at(p + ".weights", "权重值必须是数字: " + v));
                        }
                    }
                    if (Math.abs(sum - 1.0) > WEIGHT_EPSILON) {
                        errors.add(ConfigError.at(p + ".weights", "权重和 = " + sum + "，必须为 1"));
                    }
                } else {
                    errors.add(ConfigError.at(p + ".weights", "MULTI_OBJECTIVE 必须配置 weights"));
                }
            }
        }

        // 5. 交叉引用：alias → strategy 必须存在；CONDITIONAL 的 select 必须是候选子集
        for (int i = 0; i < models.size(); i++) {
            Map<String, Object> m = models.get(i);
            Object alias = m.get("alias");
            Object strategy = m.get("strategy");
            String strategyName = strategy == null || strategy.toString().isBlank()
                    ? "balanced" : strategy.toString();
            String p = "models[" + i + "]";
            if (!policyNames.contains(strategyName) && !isBuiltin(strategyName)) {
                errors.add(ConfigError.at(p + ".strategy",
                        "引用了不存在的策略: " + strategyName));
            }
            // CONDITIONAL select 子集校验（需与策略定义交叉比对，完整实现见 TODO H1 补充）
            // ——select 的每项 (channelId, model) 必须能在该别名候选里找到
        }

        // 6. 插件：name 必须在 SPI 注册表中；同名挂载去重；scope 枚举；插件自检
        List<Map<String, Object>> plugins = list(g.get("plugins"), "plugins", errors);
        Set<String> mountedNames = new HashSet<>();
        for (int i = 0; i < plugins.size(); i++) {
            String p = "plugins[" + i + "]";
            Map<String, Object> pl = plugins.get(i);
            Object name = pl.get("name");
            if (name == null || !pluginByName.containsKey(name.toString())) {
                errors.add(ConfigError.at(p + ".name", "未注册的插件: " + name));
            } else {
                // 同名去重（V2 PluginRegistry 规则上收）
                if (!mountedNames.add(name.toString())) {
                    errors.add(ConfigError.at(p + ".name", "重复挂载: " + name));
                }
                // 插件自检（V2 的 plugin.validate(config)：如 keywordRegex 必须能编译成合法正则）
                try {
                    pluginByName.get(name.toString()).validate(pl.get("config"));
                } catch (RuntimeException e) {
                    errors.add(ConfigError.at(p + ".config",
                            "插件 " + name + " 配置自检失败: " + e.getMessage()));
                }
            }
            requireEnum(pl.get("scope"), Set.of("GLOBAL", "ROUTE", "MODEL"),
                    p + ".scope", errors);
        }

        // 7. execution 段参数域校验（V3 ExecutionPolicyManager 15 条上收）
        validateExecution(g.get("execution"), errors);
        return errors;
    }

    /**
     * execution 段校验（V3 ExecutionPolicyManager.validate 上收，15 条参数域规则）。
     * 缺省段（null）不校验——绑定类缺省值兜底；出现即按规则检查。
     */
    private void validateExecution(Object node, List<ConfigError> errors) {
        if (!(node instanceof Map<?, ?> ex)) {
            return;   // 未配置 = 用缺省值
        }
        String p = "execution";
        numberGreater(ex.get("totalMs"), 0, p + ".totalMs", errors);
        if (ex.get("defaultTimeout") instanceof Map<?, ?> dt) {
            numberGreater(dt.get("connectMs"), 0, p + ".defaultTimeout.connectMs", errors);
            numberGreater(dt.get("requestMs"), 0, p + ".defaultTimeout.requestMs", errors);
            numberGreater(dt.get("firstByteMs"), 0, p + ".defaultTimeout.firstByteMs", errors);
            numberGreater(dt.get("idleMs"), 0, p + ".defaultTimeout.idleMs", errors);
        }
        if (ex.get("retry") instanceof Map<?, ?> r) {
            Number maxAttempts = asNumber(r.get("maxAttemptsPerCandidate"));
            if (maxAttempts != null && maxAttempts.doubleValue() < 1) {
                errors.add(ConfigError.at(p + ".retry.maxAttemptsPerCandidate", "必须 >= 1"));
            }
            Number jitter = asNumber(r.get("jitterRatio"));
            if (jitter != null && (jitter.doubleValue() < 0 || jitter.doubleValue() > 0.5)) {
                errors.add(ConfigError.at(p + ".retry.jitterRatio", "必须在 [0, 0.5]"));
            }
            Number base = asNumber(r.get("backoffBaseMs"));
            Number max = asNumber(r.get("backoffMaxMs"));
            if (base != null && max != null && base.doubleValue() > max.doubleValue()) {
                errors.add(ConfigError.at(p + ".retry.backoffBaseMs", "必须 <= backoffMaxMs"));
            }
            Object statuses = r.get("retryableStatuses");
            if (statuses instanceof List<?> list && list.isEmpty()) {
                errors.add(ConfigError.at(p + ".retry.retryableStatuses", "不能为空"));
            }
        }
        if (ex.get("circuitBreaker") instanceof Map<?, ?> cb) {
            Number window = asNumber(cb.get("windowSize"));
            if (window != null && window.doubleValue() < 10) {
                errors.add(ConfigError.at(p + ".circuitBreaker.windowSize", "必须 >= 10"));
            }
            Number min = asNumber(cb.get("minimumRequests"));
            if (min != null && min.doubleValue() < 1) {
                errors.add(ConfigError.at(p + ".circuitBreaker.minimumRequests",
                        "必须 >= 1"));
            }
            if (min != null && window != null && min.doubleValue() > window.doubleValue()) {
                errors.add(ConfigError.at(p + ".circuitBreaker.minimumRequests",
                        "必须 <= windowSize"));
            }
            ratioIn(cb.get("failureRateThreshold"), p + ".circuitBreaker.failureRateThreshold", errors);
            ratioIn(cb.get("slowCallRateThreshold"), p + ".circuitBreaker.slowCallRateThreshold", errors);
            numberGreater(cb.get("openDurationMs"), 0, p + ".circuitBreaker.openDurationMs", errors);
            Number halfOpen = asNumber(cb.get("halfOpenMaxRequests"));
            if (halfOpen != null && halfOpen.doubleValue() < 1) {
                errors.add(ConfigError.at(p + ".circuitBreaker.halfOpenMaxRequests", "必须 >= 1"));
            }
        }
        if (ex.get("cooldown") instanceof Map<?, ?> cd) {
            Number fails = asNumber(cd.get("consecutiveFailures"));
            if (fails != null && fails.doubleValue() < 1) {
                errors.add(ConfigError.at(p + ".cooldown.consecutiveFailures", "必须 >= 1"));
            }
            numberGreater(cd.get("cooldownMs"), 0, p + ".cooldown.cooldownMs", errors);
            Number maxCd = asNumber(cd.get("maxCooldownMs"));
            Number cdMs = asNumber(cd.get("cooldownMs"));
            if (maxCd != null && cdMs != null && maxCd.doubleValue() < cdMs.doubleValue()) {
                errors.add(ConfigError.at(p + ".cooldown.maxCooldownMs", "必须 >= cooldownMs"));
            }
        }
    }

    private void numberGreater(Object v, double min, String path, List<ConfigError> errors) {
        Number n = asNumber(v);
        if (n != null && n.doubleValue() <= min) {
            errors.add(ConfigError.at(path, "必须 > " + (long) min));
        }
    }

    /** 比率阈值：(0, 1] */
    private void ratioIn(Object v, String path, List<ConfigError> errors) {
        Number n = asNumber(v);
        if (n != null && (n.doubleValue() <= 0 || n.doubleValue() > 1)) {
            errors.add(ConfigError.at(path, "必须在 (0, 1]"));
        }
    }

    private Number asNumber(Object v) {
        return v instanceof Number n ? n : null;
    }

    // ── 工具方法（手敲时自己补全）──

    private boolean isBuiltin(String name) {
        return Set.of("balanced", "latency-first", "cost-first", "quality-first")
                .contains(name);
    }

    private List<Map<String, Object>> list(Object node, String path, List<ConfigError> errors) {
        if (node == null) {
            return List.of();          // 缺省段：空列表（缺省值由绑定类兜底）
        }
        if (node instanceof List<?> list) {
            List<Map<String, Object>> result = new ArrayList<>();
            for (Object o : list) {
                if (o instanceof Map<?, ?> map) {
                    @SuppressWarnings("unchecked")
                    Map<String, Object> m = (Map<String, Object>) map;
                    result.add(m);
                } else {
                    errors.add(ConfigError.at(path, "必须是对象列表"));
                }
            }
            return result;
        }
        errors.add(ConfigError.at(path, "必须是列表"));
        return List.of();
    }

    private void requireNumber(Object v, String path, List<ConfigError> errors) {
        if (v != null && !(v instanceof Number)) {
            errors.add(ConfigError.at(path, "必须是数字，实际是: " + v));
        }
    }

    private void requireNonNegative(Object v, String path, List<ConfigError> errors) {
        if (v instanceof Number n && n.doubleValue() < 0) {
            errors.add(ConfigError.at(path, "不能为负数"));
        }
    }

    private void requireEnum(Object v, Set<String> allowed, String path, List<ConfigError> errors) {
        if (v != null && !allowed.contains(v.toString())) {
            errors.add(ConfigError.at(path, "不支持的取值: " + v + "，可选: " + allowed));
        }
    }
}
```

## 9. 热更新核心（关键代码段 S5，🖊 H2）

### 9.1 热更新五步（先背下来）

```
解析新配置 → Schema 校验 → 预检（引用完整性 / 与现有运行对象兼容）→ 通知组件重建（先构建新对象图，全部成功才替换内部引用；任一步失败整体回滚）→ 原子替换全局引用
```

- **原子性（copy-on-write）**：先构建完整的新运行时对象图，全部成功才替换引用；在途请求继续用旧引用，天然不受影响。任何时刻系统看到的都是一份完整配置，不存在"渠道是新的、策略是旧的"混搭。

⚠️ **顺序纠正**（2026-08-10 审查）：五步中"通知组件刷新"在"原子替换全局引用"**之前**——先通知各组件重建（各自先构建新对象图、成功才替换内部引用），**全部成功后才**替换全局 `current` 引用。若先替换再通知，"通知失败回滚"无从谈起（旧引用已被覆盖）。学习版文档 4.2 的表述已同步修正。
- **失败处理**：校验 / 预检失败时，当前配置保持不变，管理接口返回可读错误（错误列表）。
- **通知失败回滚**：组件按依赖顺序（渠道 → 策略 → 插件 → 治理）逐个刷新；任一失败 → 用旧快照反向重建已成功的组件，整体回到旧版本。
- **版本化**：每次生效版本号 +1，`note` 记变更说明；历史保留 `historySize` 版，`rollback(version)` 走完整校验与预检（学习版 Q2：校验失败 = 根本不进入替换步骤，旧配置引用从未被触碰）。

### 9.2 主逻辑（代码段 S5，🖊 H2 全部手敲）

```java
package com.aigateway.config.service;

import com.aigateway.config.loader.ConfigLoader;
import com.aigateway.config.loader.ParsedConfig;
import com.aigateway.config.model.ApplyResult;
import com.aigateway.config.model.ConfigError;
import com.aigateway.config.model.GatewayConfig;
import com.aigateway.config.spi.ConfigAware;
import com.aigateway.config.validate.ConfigValidator;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import com.aigateway.infra.config.GatewayProperties;

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;
import java.util.Map;

/**
 * 热更新核心（🖊 H2 手敲）。
 *
 * 设计心法：
 * - 全局只维护一个 volatile 引用 current；读路径（任何组件、任何请求）都从
 *   current 出发，写路径（apply）串行化（synchronized）——"读无锁、写串行"，
 *   管理操作低频，串行无性能问题，换来"任何时刻看到的都是一份完整配置"；
 * - 组件刷新顺序 = 依赖顺序（渠道 → 策略 → 插件 → 治理）：
 *   渠道先重建，策略交叉引用渠道，插件挂载在策略之上，治理最后读全量快照；
 * - 失败回滚 = 用旧快照反向重建已成功组件——回滚与前进走同一条代码路径，
 *   没有"回滚专属逻辑"需要维护。
 */
@Component
public class ConfigService {

    private static final Logger log = LoggerFactory.getLogger(ConfigService.class);

    private final ConfigLoader loader;
    private final ConfigValidator validator;
    private final List<ConfigAware> components;      // 按依赖顺序注入（Spring List 保序）
    private final int historySize;

    /** 当前生效配置（copy-on-write 引用：读路径的唯一入口） */
    private volatile GatewayConfig current;

    /** 版本历史：最近 historySize 版（新 → 旧） */
    private final Deque<GatewayConfig> history = new ArrayDeque<>();

    public ConfigService(ConfigLoader loader, ConfigValidator validator,
                         List<ConfigAware> components,
                         @Value("${gateway.config.historySize:5}") int historySize) {
        this.loader = loader;
        this.validator = validator;
        // 显式按 configOrder 排序（不依赖 Spring 的 List 注入顺序）
        this.components = components.stream()
                .sorted(java.util.Comparator.comparingInt(ConfigAware::configOrder))
                .toList();
        this.historySize = historySize;
        loadInitial();
    }

    /** 启动加载：gateway.yaml → 校验 → 首个快照（version=1）。校验失败 → 启动失败（快速失败）。 */
    private void loadInitial() {
        ParsedConfig parsed = loader.loadMain();          // 读取主文件 + include 合并 + 绑定
        List<ConfigError> errors = validator.validate(parsed);
        if (!errors.isEmpty()) {
            throw new IllegalStateException("配置校验失败，启动中止:\n" + formatErrors(errors));
        }
        GatewayConfig initial = new GatewayConfig(1, "initial", System.currentTimeMillis(),
                parsed.yaml(), parsed.props(), parsed.governance(), parsed.admin());
        applyToComponents(initial);                        // 组件首次构建（失败 = 启动失败）
        this.current = initial;
        log.info("配置加载完成: version=1, channels={}, models={}, plugins={}",
                parsed.props().getChannels().size(),
                parsed.props().getModels().size(),
                parsed.props().getPlugins().size());
    }

    /**
     * 热更新五步（同步，串行）。
     *
     * @param yamlText 完整 gateway YAML 文本（Admin API PUT body）
     * @param note     变更说明（进入审计与版本历史）
     */
    public synchronized ApplyResult apply(String yamlText, String note) {
        // 1. 解析（include 合并 + 绑定；语法错误 → 失败）
        ParsedConfig parsed;
        try {
            parsed = loader.parse(yamlText);
        } catch (ConfigError e) {
            return ApplyResult.failed(List.of(e));
        }

        // 2. Schema 校验（结构 / 类型 / 引用 / 权重和 / 枚举）
        List<ConfigError> errors = validator.validate(parsed);
        if (!errors.isEmpty()) {
            return ApplyResult.failed(errors);
        }

        // 3. 预检（与现有运行对象兼容）
        List<String> warnings = new ArrayList<>();
        List<ConfigError> precheckErrors = precheck(parsed, warnings);
        if (!precheckErrors.isEmpty()) {
            return ApplyResult.failed(precheckErrors);
        }

        // 4. 构建新快照（版本号在旧版本上 +1）
        GatewayConfig next = new GatewayConfig(current.version() + 1,
                note, System.currentTimeMillis(), parsed.yaml(),
                parsed.props(), parsed.governance(), parsed.admin());

        // 5. 按依赖顺序通知组件（各自"构建新对象图 → 成功才替换内部引用"）
        GatewayConfig old = current;
        List<ConfigAware> applied = new ArrayList<>();
        try {
            for (ConfigAware c : components) {
                c.onConfigChanged(next);
                applied.add(c);
            }
        } catch (RuntimeException e) {
            // 通知失败 → 整体回滚：用旧快照重建已成功的组件
            log.error("配置通知失败，回滚到 version={}: {}", old.version(), e.getMessage());
            for (int i = applied.size() - 1; i >= 0; i--) {
                try {
                    applied.get(i).onConfigChanged(old);
                } catch (RuntimeException re) {
                    log.error("回滚组件失败（组件处于旧状态，可接受）: {}", re.getMessage());
                }
            }
            return ApplyResult.failed(List.of(ConfigError.at("runtime",
                    "配置通知失败: " + e.getMessage())));
        }

        // 原子替换全局引用 + 记录历史
        this.current = next;
        history.addFirst(next);
        while (history.size() > historySize) {
            history.pollLast();
        }
        log.info("配置生效: version={}, note={}", next.version(), note);
        return ApplyResult.success(next, warnings);
    }

    /**
     * 回滚到指定版本（走完整校验与预检——回滚不豁免检查）。
     * 找到历史版本 → 用其 YAML 原文重新 apply（版本号继续递增，note 标注回滚来源）。
     */
    public synchronized ApplyResult rollback(int version) {
        GatewayConfig target = history.stream()
                .filter(c -> c.version() == version)
                .findFirst()
                .orElse(null);
        if (target == null) {
            return ApplyResult.failed(List.of(ConfigError.at("version",
                    "版本不存在或超出保留范围: " + version)));
        }
        log.info("回滚到 version={}", version);
        return apply(target.yaml(), "rollback to version " + version);
    }

    /** 当前生效配置（组件 / 鉴权 / 审计的读入口） */
    public GatewayConfig current() {
        return current;
    }

    /** 版本历史（新 → 旧，只读视图） */
    public List<GatewayConfig> history() {
        return new ArrayList<>(history);
    }

    /**
     * 预检：Schema 通过后、与现有运行对象兼容性检查（🖊 H2 全部手敲）。
     * 失败返回错误列表（当前配置保持不变）；通过往 warnings 写非阻断提示。
     */
    private List<ConfigError> precheck(ParsedConfig parsed, List<String> warnings) {
        List<ConfigError> errors = new ArrayList<>();

        // 1. 清空保护：当前非空的关键段（channels / models / policies）在新配置中缺失或为空，
        //    视为误提交（PUT 只改了某个 section 却丢了其他 section）——拒绝，避免"热更一次全清空"事故
        for (String section : List.of("channels", "models", "policies")) {
            Object oldSec = currentSection(section);
            boolean oldEmpty = oldSec == null || (oldSec instanceof List<?> l && l.isEmpty());
            boolean newEmpty = sectionEmpty(parsed, section);
            if (!oldEmpty && newEmpty) {
                errors.add(ConfigError.at(section,
                        "新配置将清空 " + section + " 段（当前非空）。如确需清空，请先移除引用它的配置再提交"));
            }
        }

        // 2. tokens 段是"启动种子"：热更新不接受该段变更（运行时令牌一律走 Admin API）
        //    ⚠️ 审查修正：tokensOf 仅【原样提取】YAML 中的 tokens 段（不做任何字段规范化/
        //    补缺省），保证与 parsed 原始 Map 结构一致、可直接 Objects.equals 对比；
        //    若未来给 tokensOf 加规范化，本对比必须改为两侧过同一规范化后再比
        Object newTokens = parsed.root().get("tokens");
        Object oldTokens = loader.tokensOf(current.yaml());   // 从当前快照 YAML 重新解析（tokens 不进 props）
        if (!java.util.Objects.equals(oldTokens, newTokens)) {
            errors.add(ConfigError.at("tokens",
                    "tokens 段仅启动时导入；运行时令牌变更请使用 Admin API"));
        }

        // 3. 渠道 baseUrl 变更：全局单例 HttpClient，连接池按上游地址（host:port）复用，
        //    新请求走新地址、旧连接自然过期——非阻断，加警告
        Map<String, String> oldBase = channelBaseUrls(current.yaml());
        for (GatewayProperties.ChannelDef def : parsed.props().getChannels()) {
            String oldUrl = oldBase.get(def.getId());
            if (oldUrl != null && !oldUrl.equals(def.getBaseUrl())) {
                warnings.add("渠道 " + def.getId() + " baseUrl 变更: "
                        + oldUrl + " -> " + def.getBaseUrl()
                        + "（连接池按上游地址复用，在途请求不受影响）");
            }
        }
        return errors;
    }

    /** 当前快照里某 section 的非空判断（tokens / channels 等 props 之外的段从 YAML 解析） */
    private boolean sectionEmpty(ParsedConfig parsed, String section) {
        Object node = parsed.root().get(section);
        if (node == null) {
            return true;
        }
        if (node instanceof List<?> list) {
            return list.isEmpty();
        }
        return false;
    }

    /** 从 YAML 文本解析某 section（不参与 props 绑定的段：tokens / channels 的辅助读取） */
    private Object currentSection(String section) {
        try {
            ParsedConfig currentParsed = loader.parse(current.yaml());
            return currentParsed.root().get(section);
        } catch (ConfigError e) {
            return null;   // 当前配置必然合法（已在启动/热更时校验），此处仅防御
        }
    }

    /** 渠道 id → baseUrl（对比热更前后的地址变更） */
    private Map<String, String> channelBaseUrls(String yamlText) {
        Map<String, String> map = new java.util.HashMap<>();
        try {
            ParsedConfig parsed = loader.parse(yamlText);
            List<GatewayProperties.ChannelDef> defs = parsed.props().getChannels();
            for (GatewayProperties.ChannelDef def : defs) {
                map.put(def.getId(), def.getBaseUrl());
            }
        } catch (ConfigError e) {
            // 忽略（防御）
        }
        return map;
    }

    /** 组件首次构建（启动失败 = 配置与运行时对象不兼容，快速失败） */
    private void applyToComponents(GatewayConfig config) {
        for (ConfigAware c : components) {
            c.onConfigChanged(config);
        }
    }

    private String formatErrors(List<ConfigError> errors) {
        StringBuilder sb = new StringBuilder();
        for (ConfigError e : errors) {
            sb.append("  - ").append(e).append('\n');
        }
        return sb.toString();
    }
}
```

### 10.1 组件重建契约 `ConfigAware`（先背下来）

```java
package com.aigateway.config.spi;

import com.aigateway.config.model.GatewayConfig;

/**
 * 配置感知组件：热更新时被 ConfigService 按依赖顺序调用。
 *
 * 契约（学习版 4.3）：
 * - 组件收到新快照后，"构建新对象图 → 全部成功 → 原子替换内部引用"；
 * - 构建失败抛异常（内部引用不变，仍服务旧配置），ConfigService 负责整体回滚；
 * - 组件内部运行状态（EWMA 延迟、健康快照、预算已用量、限流窗口）在重建时保留，
 *   只替换"配置决定的部分"。
 *
 * 插件类组件的特殊约定（2026-08-10 审查补充）：
 * 插件是 Spring 单例 Bean（List<GatewayPlugin> 注入），configure() 会修改实例的可变字段
 * （如 CanaryGroupPlugin 的 stableInstances）。热更新无法"新建实例"，因此约定：
 * **configure 必须幂等可重入**——rebuild 用新 config 重新 validate+configure；
 * 回滚时 ConfigService 用旧 config 反向重建（重新 configure 旧值恢复）。
 * 插件作者写示例插件时遵守该约定（现有三个示例插件均幂等，可直接复用）。
 */
public interface ConfigAware {

    /** 组件重建顺序（数字小的先重建）。默认 100（靠后）；渠道 / 策略等被依赖者调小。 */
    default int configOrder() {
        return 100;
    }

    void onConfigChanged(GatewayConfig config);
}
```

组件依赖顺序（`configOrder` 升序）：`ModelRegistry(10) → PolicyManager(20) → PluginRegistry(30) → Scorer / DecisionLogStore / ModelStateStore / HealthChecker / ExecutionPolicyManager(40) → ChannelStore(50) → BudgetManager / RateLimiter(60) → GovernanceService / GovernanceFilter(70)`。ConfigService 构造时按 `configOrder` 排序（不依赖 Spring 的 List 注入顺序，显式声明依赖关系）。

### 10.2 `ModelRegistry` COW 改造（代码段 S6，🖊 H3 全部手敲）

核心思想：把三个 `ConcurrentHashMap` 字段收敛到一个 **volatile 状态对象**（State 不可变），读路径走 `state`，重建 = 构建新 State → 成功后替换 `this.state`。这就是 copy-on-write 在组件层的落地。

```java
package com.aigateway.state.registry;

import com.aigateway.config.model.GatewayConfig;
import com.aigateway.config.service.ConfigService;
import com.aigateway.config.spi.ConfigAware;
import com.aigateway.core.domain.model.Channel;
import com.aigateway.core.domain.model.ModelInstance;
import com.aigateway.infra.config.GatewayProperties;
import com.aigateway.infra.config.SecretResolver;
import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;

/**
 * 模型注册表：别名 → 候选实例 + 渠道表（🖊 H3 改造：COW）。
 *
 * V5 变化：
 * - 构造器不再注入 GatewayProperties（已不是 Bean），改为注入 ConfigService，
 *   从 current() 快照初始化；实现 ConfigAware 支持热更新重建；
 * - 三个 Map 收敛到 volatile State 对象：重建时构建新 State，全部成功才替换引用。
 *   在途请求从 state 读到的是"替换前或替换后"的完整视图，不可能读到混搭；
 * - 启动校验上收 ConfigValidator（第 8 节），本类只做"构建对象图"，
 *   不再抛 invalid_config（校验在加载层已统一拦截）。
 */
@Component
public class ModelRegistry implements ConfigAware {

    /** 不可变状态对象：读路径唯一入口 */
    public record State(
            Map<String, Channel> channels,
            Map<String, List<ModelInstance>> byAlias,
            Map<String, String> strategyByAlias) {}

    private volatile State state;

    private final SecretResolver secretResolver;

    public ModelRegistry(ConfigService configService, SecretResolver secretResolver) {
        this.secretResolver = secretResolver;
        rebuild(configService.current().props());
    }

    /** 依赖顺序：渠道最先重建（策略 / 模型交叉引用它） */
    @Override
    public int configOrder() {
        return 10;
    }

    @Override
    public void onConfigChanged(GatewayConfig config) {
        rebuild(config.props());
    }

    /** 构建新 State；任何一步失败抛异常（内部引用不变，ConfigService 负责回滚） */
    private void rebuild(GatewayProperties props) {
        Map<String, Channel> newChannels = new ConcurrentHashMap<>();
        Map<String, List<ModelInstance>> newByAlias = new LinkedHashMap<>();
        Map<String, String> newStrategy = new LinkedHashMap<>();

        for (GatewayProperties.ChannelDef def : props.getChannels()) {
            secretResolver.resolve(def.getCredentialsRef());   // 只校验格式（不存密钥值）
            newChannels.put(def.getId(), new Channel(
                    def.getId(), def.getProvider(), def.getBaseUrl(),
                    def.getCredentialsRef(), def.getWeight()));
        }

        for (GatewayProperties.ModelDef def : props.getModels()) {
            newStrategy.put(def.getAlias(),
                    def.getStrategy() == null || def.getStrategy().isBlank()
                            ? "balanced" : def.getStrategy());
            List<ModelInstance> instances = def.getCandidates().stream()
                    .map(c -> new ModelInstance(
                            c.getChannelId() + ":" + c.getModel(),   // instanceId（同 V1 规则）
                            def.getAlias(),                          // alias（对外模型名）
                            c.getChannelId(), c.getModel(),
                            c.getWeight(), c.getCapability(),
                            c.getPriceIn(), c.getPriceOut(),
                            c.getQualityScore() != null ? c.getQualityScore()
                                    : deriveQuality(c.getCapability()),  // 缺省由 qualityLevel 推导
                            c.getLatencyProfileMs() != null ? c.getLatencyProfileMs() : 1000L))
                    .toList();
            newByAlias.put(def.getAlias(), List.copyOf(instances));
        }

        // 全部构建成功 → 原子替换（写 volatile 有 happens-before，读线程可见）
        this.state = new State(Map.copyOf(newChannels), Map.copyOf(newByAlias), Map.copyOf(newStrategy));
    }

    // ── 读路径（原方法签名保持不变，改走 state）──

    public List<ModelInstance> findByAlias(String alias) {
        return state.byAlias().getOrDefault(alias, List.of());
    }

    public List<String> aliases() {
        return List.copyOf(state.byAlias().keySet());
    }

    /** 渠道查询（原方法签名：Optional——OpenAIConnector / HealthChecker 调用方依赖） */
    public Optional<Channel> findChannel(String id) {
        return Optional.ofNullable(state.channels().get(id));
    }

    /** 便捷方法（V5 新增，可选；非空渠道才调用） */
    public Channel channel(String id) {
        return state.channels().get(id);
    }
```

### 12.2 主逻辑（代码段 S8，🖊 H4 全部手敲）

```java
package com.aigateway.governance.admin;

import com.aigateway.config.model.GatewayConfig;
import com.aigateway.config.service.ConfigService;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.HandlerInterceptor;

import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.SecureRandom;
import java.util.HexFormat;
import java.util.List;

/**
 * 管理面鉴权（🖊 H4 手敲）：/v1/admin/** 的守卫。
 *
 * 设计心法：
 * - 独立于调用方令牌体系（调用令牌是"客人门票"，管理密钥是"经理钥匙"，
 *   混在一起 = 任何调用方都能改配置，安全事故）；
 * - 密钥校验用常量时间比较（MessageDigest.isEqual）——普通 equals 在
 *   "第一位不匹配就返回"时泄漏前缀信息（时序侧信道）；
 * - IP 白名单空 = 不限（本地演示），配置后严格匹配；
 * - 密钥从当前配置快照读取：热更新改 admin.apiKey 即时生效。
 */
@Component
public class AdminAuthInterceptor implements HandlerInterceptor {

    private static final Logger log = LoggerFactory.getLogger(AdminAuthInterceptor.class);
    private static final String HEADER = "X-Admin-Key";

    private final ConfigService configService;

    /** 启动时未配置密钥 → 生成的随机密钥（仅启动日志打印一次） */
    private volatile String generatedKey;

    public AdminAuthInterceptor(ConfigService configService) {
        this.configService = configService;
    }

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        GatewayConfig cfg = configService.current();
        AdminProperties admin = cfg.admin();

        // 1. IP 白名单（空 = 不限）
        List<String> whitelist = admin.getIpWhitelist();
        if (!whitelist.isEmpty() && !whitelist.contains(request.getRemoteAddr())) {
            log.warn("admin 请求被拒: IP 不在白名单: {}", request.getRemoteAddr());
            response.setStatus(403);
            response.setContentType("application/json");
            response.getWriter().write("{\"type\":\"admin_ip_denied\","
                    + "\"detail\":\"IP 不在管理面白名单\"}");
            return false;
        }

        // 2. 管理密钥校验（常量时间比较）
        String given = request.getHeader(HEADER);
        if (given == null || !constantTimeEquals(given, resolveKey(admin))) {
            log.warn("admin 请求被拒: 密钥缺失或错误, uri={}", request.getRequestURI());
            response.setStatus(401);
            response.setContentType("application/json");
            response.getWriter().write("{\"type\":\"admin_unauthorized\","
                    + "\"detail\":\"X-Admin-Key 缺失或错误\"}");
            return false;
        }
        return true;
    }

    /** 解析配置里的密钥（env: 引用 / 明文 / 空 → 随机生成） */
    private String resolveKey(AdminProperties admin) {
        String raw = admin.getApiKey();
        if (raw == null || raw.isBlank()) {
            if (generatedKey == null) {
                byte[] bytes = new byte[16];
                new SecureRandom().nextBytes(bytes);
                generatedKey = "agw-admin-" + HexFormat.of().formatHex(bytes);
                log.warn("未配置 gateway.admin.apiKey，使用随机管理密钥（仅本次启动有效）: {}", generatedKey);
            }
            return generatedKey;
        }
        if (raw.startsWith("env:")) {
            String key = System.getenv(raw.substring(4));
            if (key == null) {
                log.error("gateway.admin.apiKey 引用的环境变量不存在: {}", raw);
                return "";   // 返回空串 → 与任何输入都不等 → 恒 401（fail-closed，不放过）
            }
            return key;
        }
        return raw;
    }

    /** 常量时间字符串比较（防时序侧信道） */
    private boolean constantTimeEquals(String a, String b) {
        return MessageDigest.isEqual(
                a.getBytes(StandardCharsets.UTF_8),
                b.getBytes(StandardCharsets.UTF_8));
    }
}
```

```java
/** 管理写操作编排：改配置 → 热更 → 审计（Codex）。 */
@Service
public class AdminService {

    private final ConfigService configService;
    private final ConfigLoader loader;
    private final AuditLedger auditLedger;
    private final ObjectMapper yamlMapper = new ObjectMapper(new YAMLFactory());

    public AdminService(ConfigService configService, ConfigLoader loader, AuditLedger auditLedger) {
        this.configService = configService;
        this.loader = loader;
        this.auditLedger = auditLedger;
    }

    /**
     * 通用流程：mutator 修改合并 YAML 的 gateway 节点 → ConfigService.apply →
     * 无论成败都记审计（detail 用 ConfigDiff 生成变更摘要）。
     */
    public ApplyResult modifyConfig(Consumer<Map<String, Object>> mutator,
                                    String note, String opType, String operator) {
        GatewayConfig current = configService.current();
        Map<String, Object> root = loader.parseRoot(current.yaml());   // 反序列化当前 YAML
        mutator.accept(root);                                          // 调用方改配置
        String nextYaml;
        try {
            nextYaml = yamlMapper.writeValueAsString(root);            // 序列化回 YAML
        } catch (Exception e) {
            return ApplyResult.failed(List.of(ConfigError.at("runtime",
                    "配置序列化失败: " + e.getMessage())));
        }
        ApplyResult result = configService.apply(nextYaml, note);
        String detail = result.ok()
                ? String.join("\n", ConfigDiff.diff(current, result.config()))
                : result.errors().stream().map(ConfigError::toString).toList().toString();
        auditLedger.record(new AuditEntry(0, opType, operator, "config",
                detail, result.ok() ? "SUCCESS" : "FAILED",
                result.ok() ? "" : "apply failed", System.currentTimeMillis()));
        return result;
    }
}
```

### 14.2 变更摘要 `ConfigDiff`（代码段 S10a，🖊 H5 全部手敲）

递归 diff 两个快照（props / governance / admin → Jackson 转 Map），只输出**叶子变更**（`path: 旧值 -> 新值`），新增 / 删除也表达为 `null -> 值` / `值 -> null`：

```java
package com.aigateway.governance.audit;

import com.aigateway.config.model.GatewayConfig;
import com.fasterxml.jackson.databind.ObjectMapper;

import java.util.ArrayList;
import java.util.List;
import java.util.Map;

/**
 * 配置变更摘要生成器（🖊 H5 手敲）。
 * 递归对比新旧快照的配置 Map，输出行式变更（path: 旧 -> 新）。
 * 只输出叶子节点——聚合节点（Map/List 本身）不输出，避免"整棵配置都变了"的噪音。
 */
public class ConfigDiff {

    private static final ObjectMapper MAPPER = new ObjectMapper();

    public static List<String> diff(GatewayConfig oldCfg, GatewayConfig newCfg) {
        Map<String, Object> oldMap = toMap(oldCfg);
        Map<String, Object> newMap = toMap(newCfg);
        List<String> lines = new ArrayList<>();
        walk(oldMap, newMap, "", lines);
        return lines;
    }

    /** 对比两个 Map：递归到叶子；key 只增不减 → 输出差异行 */
    @SuppressWarnings("unchecked")
    private static void walk(Map<String, Object> oldMap, Map<String, Object> newMap,
                             String prefix, List<String> lines) {
        for (String key : union(oldMap.keySet(), newMap.keySet())) {
            String path = prefix.isEmpty() ? key : prefix + "." + key;
            Object oldVal = oldMap.get(key);
            Object newVal = newMap.get(key);
            if (oldVal instanceof Map && newVal instanceof Map) {
                walk((Map<String, Object>) oldVal, (Map<String, Object>) newVal, path, lines);
            } else if (oldVal instanceof List && newVal instanceof List) {
                walkList((List<Object>) oldVal, (List<Object>) newVal, path, lines);
            } else if (!java.util.Objects.equals(oldVal, newVal)) {
                lines.add(path + ": " + display(oldVal) + " -> " + display(newVal));
            }
        }
    }

    /** 列表按下标对比（下标即坐标，足够定位） */
    private static void walkList(List<Object> oldList, List<Object> newList,
                                 String path, List<String> lines) {
        int size = Math.max(oldList.size(), newList.size());
        for (int i = 0; i < size; i++) {
            String itemPath = path + "[" + i + "]";
            Object oldItem = i < oldList.size() ? oldList.get(i) : null;
            Object newItem = i < newList.size() ? newList.get(i) : null;
            if (oldItem instanceof Map && newItem instanceof Map) {
                @SuppressWarnings("unchecked")
                Map<String, Object> o = (Map<String, Object>) oldItem;
                @SuppressWarnings("unchecked")
                Map<String, Object> n = (Map<String, Object>) newItem;
                walk(o, n, itemPath, lines);
            } else if (!java.util.Objects.equals(oldItem, newItem)) {
                lines.add(itemPath + ": " + display(oldItem) + " -> " + display(newItem));
            }
        }
    }

    private static java.util.Set<String> union(java.util.Set<String> a, java.util.Set<String> b) {
        java.util.Set<String> r = new java.util.HashSet<>(a);
        r.addAll(b);
        return r;
    }

    private static Object display(Object v) {
        if (v == null) return "null";
        if (v instanceof String s) return "\"" + s + "\"";
        return v;
    }

    /**
     * 快照 → 配置 Map（版本号 / 时间戳 / yaml 原文不进 diff：它们是配置的"元信息"）。
     * 合并 props（gateway 段）+ governance + admin 三部分；
     * 注意 Jackson 转 Map 后 key 为 Java 字段名（camelCase，如 intervalSeconds），
     * 与 YAML 的 kebab-case 不同——diff 路径用 camelCase 展示，保持一致即可。
     */
    private static Map<String, Object> toMap(GatewayConfig cfg) {
        Map<String, Object> root = new java.util.HashMap<>();
        Map<String, Object> gateway = MAPPER.convertValue(cfg.props(), Map.class);
        gateway.put("governance", MAPPER.convertValue(cfg.governance(), Map.class));
        gateway.put("admin", MAPPER.convertValue(cfg.admin(), Map.class));
        root.put("gateway", gateway);
        return root;
    }
}
```

### 14.3 `AuditLedger`（代码段 S10b，🖊 H5 全部手敲）

```java
package com.aigateway.governance.audit;

import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.stereotype.Component;

import java.util.List;

/**
 * 审计账本（🖊 H5 手敲）：管理写操作的事后记录。
 *
 * 设计心法：
 * - 与请求日志（DecisionLogStore 环形缓冲）分离：请求日志面向调用链路（内存、可丢），
 *   审计面向管理行为（落库、不可丢）；
 * - 审计低频（管理操作），直接写库（JdbcTemplate.update），不做批量缓冲——
 *   V4 用量落库的"缓存 + 批量"是为高频请求设计的，审计用不上；
 * - record 失败不阻断主流程？不行——审计是承诺（"所有写操作进审计"），
 *   写失败要记日志告警（不静默吞掉）。
 */
@Component
public class AuditLedger {

    private final JdbcTemplate jdbc;

    public AuditLedger(JdbcTemplate jdbc) {
        this.jdbc = jdbc;
    }

    /** 写一条审计（createdAt 由调用方传入；id 由 DB 自增） */
    public void record(AuditEntry entry) {
        try {
            jdbc.update("""
                    INSERT INTO audit_log (op_type, operator, target, detail, result, error, created_at)
                    VALUES (?, ?, ?, ?, ?, ?, ?)""",
                    entry.opType(), entry.operator(), entry.target(),
                    truncate(entry.detail(), 2000), entry.result(), entry.error(),
                    entry.createdAt());
        } catch (RuntimeException e) {
            // 审计写失败必须告警（承诺不可静默吞）
            log.error("审计写入失败: {}", e.getMessage());
            throw e;
        }
    }

    /** 按条件过滤查询（全部可选；limit 缺省 50，最多 500） */
    public List<AuditEntry> query(String operator, String opType, String target,
                                  Long from, Long to, int limit) {
        StringBuilder sql = new StringBuilder("""
                SELECT id, op_type, operator, target, detail, result, error, created_at
                FROM audit_log WHERE 1=1""");
        List<Object> args = new java.util.ArrayList<>();
        if (operator != null && !operator.isBlank()) {
            sql.append(" AND operator = ?"); args.add(operator);
        }
        if (opType != null && !opType.isBlank()) {
            sql.append(" AND op_type = ?"); args.add(opType);
        }
        if (target != null && !target.isBlank()) {
            sql.append(" AND target LIKE ?"); args.add("%" + target + "%");
        }
        if (from != null) { sql.append(" AND created_at >= ?"); args.add(from); }
        if (to != null)   { sql.append(" AND created_at <= ?"); args.add(to); }
        sql.append(" ORDER BY id DESC LIMIT ?");
        args.add(Math.max(1, Math.min(limit, 500)));
        return jdbc.query(sql.toString(), (rs, i) -> new AuditEntry(
                rs.getLong("id"), rs.getString("op_type"), rs.getString("operator"),
                rs.getString("target"), rs.getString("detail"), rs.getString("result"),
                rs.getString("error"), rs.getLong("created_at")), args.toArray());
    }

    private static String truncate(String s, int max) {
        return s == null ? "" : (s.length() <= max ? s : s.substring(0, max));
    }
}
```

> ⚠️ 手敲要求：补齐 `AuditLedger` 里缺少的 `log` 字段（`private static final Logger log = LoggerFactory.getLogger(AuditLedger.class);`）与对应 import（`org.slf4j.Logger` / `LoggerFactory`）。`ConfigDiff` 已用全限定名 `java.util.Set`，无需补 import。

## 20. 风险与注意点

1. **组件改造遗漏**：构造器注入 `GatewayProperties` / `GovernanceProperties` 的组件全部要切换（第 2.2 节清单 17 个：7 个 props 组件 + 10 个 governance/引擎组件）；两注解同时移除后 Spring 不再提供 Bean，漏改的组件启动直接 NoSuchBeanDefinitionException——**强提示，不会静默出错**。启动报错后对照清单补齐即可。T1 验收要求先跑一遍确认报错组件清单与改造清单一致。
2. **校验上收的口径一致性**：ConfigValidator 是全量校验（一次返回全部错误），组件里原有的"两阶段校验"（如 PolicyManager 的 CONDITIONAL defaultStrategy 需全部注册后再校验）天然满足——校验器就是全量视图。**删除组件里的重复校验**，只保留对象图构建，否则同一错误两处报、措辞不一致。
3. **并发与原子性**：apply 必须 synchronized（管理操作低频，串行无性能问题）；组件 rebuild 必须"先构建后替换"（构建失败抛异常、内部引用不变）；ConfigService 通知失败用旧快照反向重建（第 9.2 节代码已实现）。
4. **tokens 段不能热更**：安全边界——凭证不能进配置明文；运行时令牌变更（创建/吊销/额度）一律走 Admin API，审计在 AdminService 层统一记录。
5. **ChannelStore 的 DB 覆盖必须移除**：否则热更改的权重被 DB 值覆盖，演示 A 不生效（第 2.1 节）；`channel` 表保留软删标记用途，别把表删了。
6. **Binder 与 @ConfigurationProperties 语义差异**：去掉注解后 Spring 不再自动绑定，必须由 ConfigLoader 显式 bind；宽松绑定（interval-seconds ↔ intervalSeconds）两者一致；绑定失败（理论上被校验器拦截）要包装为 ConfigError 而非裸异常。
7. **审计不含明文**：令牌创建审计只记 id/name/额度，**绝不记明文密钥**（V4 风险 1 同款）。
8. **回滚也是 apply**：rollback 复用 apply（同一校验/预检/通知链路），不要写"回滚专属捷径"——那是唯一能绕过校验的旁路。
9. **虚拟线程与 synchronized**：apply 用 synchronized 会短暂阻塞（管理请求低频，可接受）；不要在数据面请求路径上加锁（读路径全部无锁）。
10. **删除文件需确认**：`model.yml` 改名、`DecisionDebugController` 下线——涉及删除一律先经你确认（全局规则）。
