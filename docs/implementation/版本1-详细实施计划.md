## 1. 目标与范围

版本 1 完成后，系统支持：

- `POST /v1/chat/completions`：非流式与流式（SSE）两种调用。
- `GET /v1/models`：列出已注册的模型别名。
- 配置驱动：`channels`（渠道）+ `models`（别名 → 候选），启动时完整校验。
- 加权随机路由 + 健康过滤 + 失败切换（最多尝试 N 个候选）。
- mock 服务可动态调延迟、故障率、健康状态。
- 全链路请求 ID、结构化日志、基础指标。

**非目标**：插件框架（V2）、重试退避/熔断/冷却（V3）、令牌/限流/计量（V4）、热更新（V5）。

### 7.2 密钥解析（代码段 S5a）

```java
// 路径：ai-gateway/src/main/java/com/aigateway/infra/config/SecretResolver.java
@Component
public class SecretResolver {
    /** 支持 "env:XXX" 或空字符串；启动时解析，运行期只保存值 */
    public Optional<String> resolve(String credentialsRef) {
        if (credentialsRef == null || credentialsRef.isBlank()) {
            return Optional.empty(); // 空引用 = 无需密钥
        }
        if (credentialsRef.startsWith("env:")) {
            String var = credentialsRef.substring(4); // 去掉 env: 前缀
            return Optional.ofNullable(System.getenv(var));
        }
        // 不支持的引用格式：启动期直接报错，避免运行时才发现
        throw new GatewayException(500, "invalid_config",
                "credentialsRef 只支持 env: 引用: " + credentialsRef);
    }
}
```

### 7.3 `ModelRegistry` 构建与校验（代码段 S5b）

```java
    private void init(GatewayProperties props) {
        // ============================================================
        // H5（手敲）：启动校验（当前为已完成版，对照 TODO 逐条理解）
        // 1) 渠道：credentialsRef 必须可解析（secretResolver.resolve 抛错即启动失败）
        // 2) 模型：alias 非空；候选非空；权重 > 0；候选引用的渠道必须存在
        // 3) 重复 alias 应拒绝
        // 校验失败统一抛 GatewayException(500, "invalid_config", 可读信息)
        // ============================================================

        // 1. 渠道：先解析密钥引用（只做校验、不保存值），缺失即启动失败
        for (GatewayProperties.ChannelDef def : props.getChannels()) {
            secretResolver.resolve(def.getCredentialsRef());
            channels.put(def.getId(), new Channel(
                    def.getId(), def.getProvider(), def.getBaseUrl(),
                    def.getCredentialsRef(), def.getWeight()));
        }

        // 2. 模型候选：逐条校验 alias / 候选非空 / 渠道存在 / 权重 > 0 / 重复 alias
        Set<String> seenAliases = new HashSet<>();
        for (GatewayProperties.ModelDef def : props.getModels()) {
            if (def.getAlias() == null || def.getAlias().isBlank()) {
                throw new GatewayException(500, "invalid_config", "models 中存在空 alias");
            }
            // 重复 alias 会让后配置的静默覆盖先配置的，客户端路由结果不可预期，必须拒绝
            if (!seenAliases.add(def.getAlias())) {
                throw new GatewayException(500, "invalid_config",
                        "重复的 alias: " + def.getAlias());
            }
            if (def.getCandidates().isEmpty()) {
                throw new GatewayException(500, "invalid_config",
                        "alias[" + def.getAlias() + "] 没有任何候选");
            }
            List<ModelInstance> instances = def.getCandidates().stream().map(c -> {
                Channel channel = channels.get(c.getChannelId());
                // 候选引用的渠道必须已配置
                if (channel == null) {
                    throw new GatewayException(500, "invalid_config",
                            "alias[" + def.getAlias() + "] 引用了不存在的渠道: " + c.getChannelId());
                }
                // 权重必须为正：权重是比例分母，<=0 会导致路由算法出问题
                if (c.getWeight() <= 0) {
                    throw new GatewayException(500, "invalid_config",
                            "alias[" + def.getAlias() + "] 存在非正权重");
                }
                // instanceId = channelId:model，同一渠道下不同模型互不冲突
                return new ModelInstance(
                        c.getChannelId() + ":" + c.getModel(),
                        def.getAlias(), c.getChannelId(), c.getModel(),
                        c.getWeight(), c.getCapability());
            }).toList();
            byAlias.put(def.getAlias(), List.copyOf(instances));
        }

        // 3. 空配置兜底：一个模型都没有的网关没有意义，直接启动失败
        if (byAlias.isEmpty()) {
            throw new GatewayException(500, "invalid_config", "未配置任何模型");
        }
    }
```

## 8. 加权随机选择（关键代码段 S6）

这是 V1 的核心算法：权重累加区间 + 随机落点。

```java
package com.aigateway.core.service;

import com.aigateway.core.domain.model.ModelInstance;

import java.util.List;
import java.util.Optional;
import java.util.concurrent.ThreadLocalRandom;

/**
 * 加权随机选择器（不可变，构建后线程安全）。
 * 算法：把候选按权重在数轴上依次累加，随机数落在哪个区间就选谁。
 *   候选A 权重8 → 区间 [0, 8)
 *   候选B 权重2 → 区间 [8, 10)
 * 选中概率 = 自己的权重 / 总权重。
 */
public final class WeightedRandomPicker {

    private final List<ModelInstance> candidates; // 候选列表（防御性拷贝）
    private final int[] cumulative;   // cumulative[i] = 前 i+1 个候选的权重和
    private final int totalWeight;    // 所有权重之和 = 数轴总长度

    public WeightedRandomPicker(List<ModelInstance> candidates) {
        this.candidates = List.copyOf(candidates); // 不可变快照，线程安全
        this.cumulative = new int[candidates.size()];
        int sum = 0;
        for (int i = 0; i < candidates.size(); i++) {
            sum += candidates.get(i).weight();
            cumulative[i] = sum; // 第 i 个候选的区间右端点
        }
        this.totalWeight = sum;
    }

    public boolean isEmpty() {
        return totalWeight <= 0; // 空列表或全 0 权重
    }

    public Optional<ModelInstance> pick() {
        if (isEmpty()) {
            return Optional.empty();
        }
        // [0, totalWeight) 的随机数：右开区间保证不越界
        int r = ThreadLocalRandom.current().nextInt(totalWeight);
        for (int i = 0; i < cumulative.length; i++) {
            if (r < cumulative[i]) { // 落在第 i 个区间 → 选中第 i 个候选
                return Optional.of(candidates.get(i));
            }
        }
        return Optional.of(candidates.get(candidates.size() - 1)); // 防御兜底
    }
}
```

边界行为（写单测时逐条验证）：

- 权重 8:2 → 选中概率约 80% / 20%；
- 单个候选、权重任意 → 永远选中；
- 空列表 → `isEmpty()` 为 true；
- 候选顺序不影响正确性（只影响区间划分）。

## 9. 主流程：路由 + 转发 + 失败切换（关键代码段 S7）

```java
package com.aigateway.core.service;

@Service
public class ChatGatewayService {

    private final ModelRegistry registry;      // 别名 → 候选实例
    private final HealthChecker healthChecker; // 渠道健康快照（H4）
    private final OpenAIConnector connector;   // 上游调用 + SSE（H3）
    private final GatewayMetrics metrics;      // 指标计数

    // Spring 构造器注入四个依赖
    public ChatGatewayService(ModelRegistry registry,
                              HealthChecker healthChecker,
                              OpenAIConnector connector,
                              GatewayMetrics metrics) {
        this.registry = registry;
        this.healthChecker = healthChecker;
        this.connector = connector;
        this.metrics = metrics;
    }

    /** 非流式：失败时换下一个候选，最多尝试 maxAttempts 个（阻塞式） */
    public ChatCompletion complete(ChatRequest request, String requestId) {
        // 1. 取候选 + 健康过滤：isHealthy 是内存快照读，零阻塞
        List<ModelInstance> candidates = healthyCandidates(request.model());
        if (candidates.isEmpty()) {
            throw new GatewayException(503, "no_available_model",
                    "模型[" + request.model() + "] 当前没有可用实例");
        }
        int attempt = 0;
        while (attempt < maxAttempts() && !candidates.isEmpty()) {
            // 2. 加权随机选一个候选（H1）
            ModelInstance chosen = pick(request, requestId, candidates);
            try {
                // 3. 调用上游；成功就计数并返回
                ChatCompletion completion = connector.complete(chosen, request);
                metrics.success(request.model(), chosen.instanceId());
                return completion;
            } catch (Exception e) {
                // 4. 失败：计数、日志、排除该候选后重新加权随机（下一轮）
                metrics.failure(request.model(), chosen.instanceId());
                log(requestId, "候选失败，尝试下一个", chosen.instanceId() + " - " + e.getMessage());
                candidates = remaining(candidates, chosen);
                attempt++;
            }
        }
        throw new GatewayException(502, "upstream_failed", "所有候选均失败");
    }

    private ModelInstance pick(ChatRequest request, String requestId, List<ModelInstance> candidates) {
        ModelInstance chosen = new WeightedRandomPicker(candidates).pick()
                .orElseThrow(() -> new GatewayException(503, "no_available_model", "候选为空"));
        log(requestId, "路由选择", chosen.instanceId());
        return chosen;
    }

    /** 流式：首字节前失败才切换候选；已经开始输出则直接中断（V3 安全重试边界） */
    public void stream(ChatRequest request, String requestId, Consumer<ChatChunk> consumer) {
        List<ModelInstance> candidates = healthyCandidates(request.model());
        if (candidates.isEmpty()) {
            throw new GatewayException(503, "no_available_model",
                    "模型[" + request.model() + "] 当前没有可用实例");
        }
        int attempt = 0;
        while (attempt < maxAttempts() && !candidates.isEmpty()) {
            ModelInstance chosen = pick(request, requestId, candidates);
            boolean[] started = {false}; // 数组技巧：lambda 里可修改标记位
            try {
                connector.stream(chosen, request, chunk -> {
                    metrics.streamChunk(request.model(), chosen.instanceId());
                    started[0] = true; // 只要有 chunk 到达，就标记已开始输出
                    consumer.accept(chunk);
                });
                return;
            } catch (Exception e) {
                if (started[0]) {
                    // 已开始输出后失败：不能安全重试（客户端会收到重复内容），直接中断
                    throw new GatewayException(502, "upstream_failed",
                            "流式输出中断: " + e.getMessage(), e);
                }
                // 首字节前失败：与 complete() 一样排除候选后重试
                metrics.failure(request.model(), chosen.instanceId());
                log(requestId, "流式候选失败(首字节前)，尝试下一个",
                        chosen.instanceId() + " - " + e.getMessage());
                candidates = remaining(candidates, chosen);
                attempt++;
            }
        }
        throw new GatewayException(502, "upstream_failed", "所有候选均失败");
    }

    private List<ModelInstance> remaining(List<ModelInstance> candidates, ModelInstance chosen) {
        return candidates.stream()
                .filter(c -> !c.instanceId().equals(chosen.instanceId()))
                .toList();
    }

    private List<ModelInstance> healthyCandidates(String alias) {
        return registry.findByAlias(alias).stream()
                .filter(inst -> healthChecker.isHealthy(inst.channelId()))
                .toList();
    }

    private int maxAttempts() {
        return 2; // 可配置化（V5 热更新），V1 先用常量
    }

    /** 结构化日志：[requestId=xxx] event=xxx detail=xxx，便于按 ID 串联全链路 */
    private static void log(String requestId, String event, String detail) {
        System.out.printf("[requestId=%s] event=%s detail=%s%n", requestId, event, detail);
    }
}
```

设计要点：

- 每次尝试用“剩余候选”重新做加权随机（而不是固定顺序），保证失败切换后权重仍然生效；
- 非流式切换 = 简单换候选（V1），V3 再引入重试退避/熔断；
- 流式目前也只处理“首字节前”的失败——这个边界从 V1 就写清楚，V3 直接沿用。

## 10. Connector：非流式 + 流式 SSE（关键代码段 S8）

```java
package com.aigateway.execution.connector;

@Component
public class OpenAIConnector {

    private final HttpClient httpClient;       // 连接池复用（HttpClientFactory 提供）
    private final ModelRegistry registry;      // 查渠道 baseUrl / 鉴权配置
    private final SecretResolver secretResolver; // env: 密钥引用解析
    private final ObjectMapper objectMapper;   // 请求序列化 + 响应/SSE 反序列化

    public OpenAIConnector(HttpClient httpClient,
                           ModelRegistry registry,
                           SecretResolver secretResolver,
                           ObjectMapper objectMapper) {
        this.httpClient = httpClient;
        this.registry = registry;
        this.secretResolver = secretResolver;
        this.objectMapper = objectMapper;
    }

    public ChatCompletion complete(ModelInstance instance, ChatRequest request) {
        // 1. 构建请求：POST {渠道baseUrl}/v1/chat/completions
        HttpRequest.Builder builder = HttpRequest.newBuilder()
                .uri(URI.create(channelBaseUrl(instance) + "/v1/chat/completions"))
                .header("Content-Type", "application/json")
                .header("Accept", "application/json")
                .timeout(Duration.ofSeconds(30))
                .POST(HttpRequest.BodyPublishers.ofString(writeJson(request)));
        // 2. 渠道需要鉴权时附加 Authorization: Bearer xxx
        applyAuth(builder, instance);
        try {
            // 3. 阻塞发送：虚拟线程挂起等待，不占平台线程
            HttpResponse<String> response = httpClient.send(builder.build(),
                    HttpResponse.BodyHandlers.ofString());
            // 4. 非 2xx：把状态码和响应体带进错误，方便排查
            if (response.statusCode() / 100 != 2) {
                throw new GatewayException(502, "upstream_error",
                        "上游返回 " + response.statusCode() + ": " + response.body());
            }
            // 5. 反序列化为类型化 DTO
            return objectMapper.readValue(response.body(), ChatCompletion.class);
        } catch (GatewayException e) {
            throw e; // 业务异常直接上抛
        } catch (IOException | InterruptedException e) {
            Thread.currentThread().interrupt(); // 恢复中断标记（线程最佳实践）
            throw new GatewayException(502, "upstream_failed", "调用上游失败: " + e.getMessage(), e);
        }
    }

    public void stream(ModelInstance instance, ChatRequest request, Consumer<ChatChunk> consumer) {
        // 1. 构建流式请求：Accept: text/event-stream；body 强制 stream=true
        HttpRequest.Builder builder = HttpRequest.newBuilder()
                .uri(URI.create(channelBaseUrl(instance) + "/v1/chat/completions"))
                .header("Content-Type", "application/json")
                .header("Accept", "text/event-stream")
                .timeout(Duration.ofSeconds(30))
                .POST(HttpRequest.BodyPublishers.ofString(writeJson(request.withStream(true))));
        applyAuth(builder, instance);
        try {
            // 2. 用 InputStream 接收：不把整个响应体读进内存，边读边转发
            HttpResponse<InputStream> response = httpClient.send(builder.build(),
                    HttpResponse.BodyHandlers.ofInputStream());
            // 3. 非 2xx：InputStream 需要手动读完错误体再抛异常
            if (response.statusCode() / 100 != 2) {
                String body = new String(response.body().readAllBytes(), StandardCharsets.UTF_8);
                throw new GatewayException(502, "upstream_error",
                        "上游返回 " + response.statusCode() + ": " + body);
            }
            // 4. 逐行读取 SSE：一行一解析一转发，不攒批（保持流式）
            try (BufferedReader reader = new BufferedReader(
                    new InputStreamReader(response.body(), StandardCharsets.UTF_8))) {
                String line;
                while ((line = reader.readLine()) != null) {
                    ChatChunk chunk = parseSseLine(line);
                    if (chunk != null) {
                        consumer.accept(chunk);
                    }
                }
            }
        } catch (GatewayException e) {
            throw e;
        } catch (IOException | InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new GatewayException(502, "upstream_failed", "流式调用上游失败: " + e.getMessage(), e);
        }
    }

    /** 解析 "data: {...}" / "data: [DONE]"；非 data 行返回 null */
    private ChatChunk parseSseLine(String line) {
        String trimmed = line.trim();
        if (!trimmed.startsWith("data:")) {
            return null; // 忽略注释 / 心跳等非数据行
        }
        String payload = trimmed.substring(5).trim(); // 去掉 "data:" 前缀
        if ("[DONE]".equals(payload)) {
            return null; // 流结束标记：调用方据此结束循环
        }
        try {
            return objectMapper.readValue(payload, ChatChunk.class);
        } catch (IOException e) {
            throw new GatewayException(502, "bad_upstream_sse",
                    "上游返回了无法解析的 SSE 数据: " + payload);
        }
    }

    /** 按渠道配置附加鉴权头；密钥来自 SecretResolver（env: 引用） */
    private void applyAuth(HttpRequest.Builder builder, ModelInstance instance) {
        registry.findChannel(instance.channelId())
                .filter(Channel::needAuth)
                .ifPresent(ch -> secretResolver.resolve(ch.credentialsRef())
                        .ifPresent(token -> builder.header("Authorization", "Bearer " + token)));
    }

    private String writeJson(Object body) {
        try {
            return objectMapper.writeValueAsString(body);
        } catch (IOException e) {
            throw new GatewayException(500, "internal_error", "请求序列化失败", e);
        }
    }

    private String channelBaseUrl(ModelInstance instance) {
        return registry.findChannel(instance.channelId())
                .map(Channel::baseUrl)
                .orElseThrow(() -> new GatewayException(500, "invalid_config",
                        "渠道不存在: " + instance.channelId()));
    }
}
```

说明：

- 用 `BufferedReader` 逐行读取上游 SSE 文本，解析 `data:` 前缀即可；
- `parseSseLine` 返回 `null` 表示忽略该行；JSON 解析失败抛 `GatewayException` 中断整个流；
- 真实上游若带鉴权头，`applyAuth` 会从渠道配置的 `env:` 引用取密钥。

                        }

            // HttpMessageConverter 路径（不支持 SseEmitter），实测 500
            return emitter;

        return ResponseEntity.ok(gatewayService.complete(request, requestId));

    @ExceptionHandler(Exception.class)

## 13. 健康检查改进（关键代码段 S13）

在现有 `HealthChecker` 基础上增加“连续失败阈值 + 快照查询”：

```java
@Component
public class HealthChecker {
    private final GatewayProperties props;    // 间隔/超时/阈值
    private final ModelRegistry registry;     // 渠道表（探活对象）
    private final HttpClient httpClient;      // 复用 HTTP 客户端
    private final ObjectMapper objectMapper;  // 解析 /health JSON

    // 并发容器：定时线程写、路由线程读，保证可见性
    private final Map<String, Integer> consecutiveFailures = new ConcurrentHashMap<>();
    private final Map<String, Boolean> healthy = new ConcurrentHashMap<>();  // 最新快照

    public void start() {  // @PostConstruct 已实现：定时调度
        // 单线程调度器：探活是阻塞调用，串行执行避免并发探活互相干扰
        Executors.newSingleThreadScheduledExecutor().scheduleAtFixedRate(
                this::checkAll, 0, props.getHealth().getIntervalSeconds(), TimeUnit.SECONDS);
    }

    private void checkAll() {
        // 遍历所有渠道（按渠道去重），逐个探活
        registry.findAll().stream()
                .map(ModelInstance::channelId)
                .distinct()
                .forEach(this::checkOne);
    }

    private void checkOne(String channelId) {
        registry.findChannel(channelId).ifPresent(ch ->
                mark(channelId, probe(ch.baseUrl())));
    }

    /** 阻塞式探活：GET /health，200 且 status=UP 视为健康；任何异常视为不健康 */
    private boolean probe(String baseUrl) {
        try {
            HttpRequest request = HttpRequest.newBuilder()
                    .uri(URI.create(baseUrl + "/health"))
                    .timeout(Duration.ofMillis(props.getHealth().getTimeoutMs()))
                    .GET()
                    .build();
            HttpResponse<String> response = httpClient.send(request,
                    HttpResponse.BodyHandlers.ofString());
            if (response.statusCode() != 200) {
                return false;
            }
            Map<?, ?> body = objectMapper.readValue(response.body(), Map.class);
            return "UP".equals(body.get("status"));
        } catch (Exception e) {
            return false; // 超时/连接失败/解析失败一律判不健康
        }
    }

    /** 状态转换：up 清零计数并置健康；连续失败达到阈值才置不健康（给恢复留缓冲） */
    private void mark(String channelId, boolean up) {
        if (up) {
            consecutiveFailures.put(channelId, 0);
            healthy.put(channelId, true);
        } else {
            int fails = consecutiveFailures.merge(channelId, 1, Integer::sum);
            if (fails >= props.getHealth().getConsecutiveFailures()) {
                healthy.put(channelId, false);
            }
        }
    }

    /** 路由调用：读快照，不做实时探测；首次探活前默认放行 */
    public boolean isHealthy(String channelId) {
        return healthy.getOrDefault(channelId, true);
    }
}
```

注意：

- 健康状态按**渠道**维护（V1 粒度），路由按渠道过滤；
- `isHealthy` 是纯内存读，请求路径零阻塞；
- mock 的 `/health` 返回 `status: DOWN` 时，连续 3 个周期后该渠道被剔除。

### 14.1 流式接口改为标准 `POST + SSE`

> 注：H2 = 失败切换（V1 手敲编号体系：H1 加权随机 / H2 失败切换 / H3 流式 / H4 健康检查 / H5 启动校验），下文注释中的 H2/H3 即此含义。

```java
// mock-model-server/src/main/java/com/aigateway/mock/controller/ChatController.java
// 统一入口：POST /v1/chat/completions，按请求体里的 stream 字段分流：
// true → SSE 流式；否则非流式 JSON（OpenAI 约定 stream 是请求体字段，不是查询参数，
// 所以用 @PostMapping + 读 body 分流，而不是 @PostMapping(params=...)）
@PostMapping("/v1/chat/completions")
public Object chat(@RequestBody Map<String, Object> request) {
    if (Boolean.TRUE.equals(request.get("stream"))) {
        return chatStream(request);
    }
    return chatOnce(request); // 非流式：既有实现（V1）
}

/** 流式推理：SseEmitter 让 Spring 自动按 data: 帧格式输出，网关端逐行读取即可 */
private SseEmitter chatStream(Map<String, Object> request) {
    ModelProfile profile = registry.getProfile();
    String content = gen.generate(profile);
    // 故障注入：流式“首字节前”失败，正好演示网关 H2/H3 的切换边界
    if (gen.shouldFail(profile)) {
        throw new RuntimeException("Mock model internal error");
    }
    String[] tokens = splitIntoTokens(content, profile.responseStyle()); // 切成增量
    String id = "chatcmpl-" + UUID.randomUUID().toString().substring(0, 8);
    SseEmitter emitter = new SseEmitter(0L); // 0 = 不设超时
    Thread.ofVirtual().name("mock-sse-" + id).start(() -> { // 每个流一个虚拟线程
        registry.requestStarted();
        try {
            for (String token : tokens) {
                emitter.send(buildChunk(id, profile.name(), token, false)); // 增量 chunk
                Thread.sleep((long) profile.streamingDelayMs());            // 模拟生成速率
            }
            emitter.send(buildChunk(id, profile.name(), "", true)); // 结束 chunk
            emitter.complete();
        } catch (Exception e) {
            emitter.completeWithError(e);
        } finally {
            registry.requestFinished();
        }
    });
    return emitter;
}
```

要点：`SseEmitter` 让 Spring 自动按 `data:` 格式输出，网关端用 `BufferedReader` 逐行读取即可。

关键测试示例（代码段 S15）：

```java
// 路径：ai-gateway/src/test/java/com/aigateway/core/service/WeightedRandomPickerTest.java
class WeightedRandomPickerTest {
    @Test
    void weightedDistribution_shouldFollowWeights() {
        // 权重 8:2，跑 1000 次：a 的出现次数应接近 800（宽松区间防 flaky）
        var a = instance("a", 8);
        var b = instance("b", 2);
        var picker = new WeightedRandomPicker(List.of(a, b));

        int countA = 0;
        for (int i = 0; i < 1000; i++) {
            if (picker.pick().orElseThrow().instanceId().equals("a")) countA++;
        }
        assertThat(countA).isBetween(750, 850);   // 8/10 概率，宽松区间
    }

    @Test
    void emptyPicker_shouldReturnEmpty() {
        // 空列表边界：isEmpty() 为 true，pick() 为空
        var picker = new WeightedRandomPicker(List.of());
        assertThat(picker.isEmpty()).isTrue();
        assertThat(picker.pick()).isEmpty();
    }
}
```

## 19. 风险与注意点

1. **SSE 帧格式**：`SseEmitter` 输出与上游 `data:` 行解析都要先跑通再写业务逻辑；建议 H3 先做“网关 → mock 流式”的最小联调。
2. **流式读取**：JDK HttpClient + `BufferedReader` 逐行读 SSE 并即时转发；不要先攒完整响应再转发（会失去流式意义）。
3. **健康检查调度**：探活是阻塞调用，跑在单线程 `ScheduledExecutorService` 上（V1 渠道少没问题；渠道多时保证 渠道数 × timeoutMs 不超过 intervalSeconds）；`consecutiveFailures`/`healthy` 用 `ConcurrentHashMap`，路由线程读快照零阻塞。
4. **Map 出入参的坑**：现有代码用 `Map` 透传，重构为 DTO 后要处理未知字段——record 默认不忽略未知字段，必须显式加 `@JsonIgnoreProperties(ignoreUnknown = true)`（请求/响应 DTO 共 4 个，其中 ChatRequest / ChatCompletion / ChatChunk 顶层均已加；ModelsResponse 只做序列化出参、不反序列化未知字段，未加）。
5. **mock 多实例**：两个 mock 用不同端口启动，但共享同一份代码；确认 `ModelRegistry`（mock 侧）按启动参数选择 `ModelProfile`，避免两个实例配置互相覆盖。
